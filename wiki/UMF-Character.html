Ultimate MUGEN Wiki

Creating a UMF character

UMF (Ultimate Mugen Format) describes a whole fighter in one JSON file. The compiler (crates/native/src/compile.rs) generates commands, states, HitDefs, projectiles, super pause, cancels and hitboxes. The result runs on the same state machine as M.U.G.E.N characters.

How a move is defined

This is an excerpt of the jab entry from Kaito’s definition. It belongs in moves, and anim refers to an entry in anims.

{
  "id": "jab",
  "name": "Snap Jab",
  "input": "x",
  "kind": "normal",
  "anim": "jab",
  "hits": [{ "at": 2, "damage": 28, "level": "light", "hitstun": 13 }],
  "cancels": ["strong", "gale", "rise", "tide", "launcher", "overhead", "slide", "string_a"]
}

at: 2 selects the second animation frame. Each frame’s ticks value sets its duration at 60 simulation ticks per second. The compiler produces the input command, combat state and HitDef for damage and hit reaction. cancels lists the move IDs that can follow before the current animation finishes.

Step by step

  1. Copy a finished fighter as a base: cp assets/chars/kaito.json assets/chars/mine.json.
  2. Change id (unique, lowercase, no spaces), name, series, author and color.
  3. Optional: add the id to assets/chars/index.json to set its order in the select screen. Missing ones follow alphabetically.
  4. Run cargo run --release. build.rs embeds every .json in the folder into the executable.
  5. Test in Training with F2 on to see hitboxes and hurtboxes.

UMF fighters also load from a folder without recompiling: drop the .json in umf/ next to the game (or in mugen/umf/, or in the folder named by UME_UMF_DIR). Kit files in the same folder are registered first, whatever their names.

Reuse: extends, use and kits

A fighter does not have to be written from scratch. Three tools remove the copy and paste that M.U.G.E.N packages need (see the numbers in M.U.G.E.N code study):

ToolWhereWhat it does
"extends": "kaito"top levelInherits everything from a loaded fighter or kit: stats, art, animations, moves. A list (["kaito", "storm-kit"]) layers several, left to right.
"use": "gale"inside a moveClones another move (from a parent or from an earlier move of the same file) under a new id, changing only the fields you write.
kit file"format": "umf-kit/1"A partial definition (moves, animations, poses, stats) with an id, shared by many fighters. core is built in and carries the universal launcher and escape_burst.

Rules of the merge, applied by crates/native/src/kit.rs before the normal UMF parser runs:

  • Objects (stats, art, abilities, passives) merge key by key, so "stats": { "life": 1080 } changes one number. An animation in anims replaces the inherited one as a whole. A value of null removes the inherited key.
  • moves are matched by id. An entry with only some fields keeps the rest ({ "id": "gale", "name": "Crimson Gale" }), a bare string ("launcher") lists an inherited move unchanged, and { "id": "slide", "remove": true } drops one. Moves you list come first, in your order; inherited moves you did not mention follow.
  • Identity is personal: name, author, description, profile, boss and npc are never inherited from a fighter.
  • spriteSet lets the new fighter reuse the parent's pixel-art pack. Recolour it with palettes and leave art.style.colors inherited: those are the reference colours of the pack.
  • Mistakes name the culprit (unknown kit or fighter, move x uses y, which no kit or earlier move defines), and extends chains deeper than 8 are rejected.

Profile (nationality and biography)

Every fighter has a nationality and a short biography, written in English (en), Brazilian Portuguese (pt) and Spanish (es). A missing language falls back to en.

"profile": {
  "country": "jp",
  "nationality": { "en": "Japanese", "pt": "Japonês", "es": "Japonés" },
  "bio": { "en": "Two short sentences.", "pt": "Duas frases curtas.", "es": "Dos frases cortas." }
}
  • Built-in fighters, the final boss and the Story mode thugs keep their profiles in assets/char_profiles.json, keyed by id. A profile field inside the fighter file wins over that table, so imported UMF fighters carry their own.
  • country picks the flag drawn next to the nationality: jp, br, no, us, cn, es, mn, de, kr, ar, au, ru, fr, plus the fictional underworld and eclipse. Flags are vector shapes in src/flag/designs.rs (no image files); add a new entry there for another country. An unknown code simply shows no flag. UME_SHOTS_ONLY=flags saves a sheet with every flag.
  • The flag appears on the roster tile, on the fighter card, in the profile strip under the roster and on the Story mode stage card.
  • Keep each biography under 260 characters: it must fit two lines of the select screen.
  • tags is an optional list of fighting-style tags ("tags": ["rushdown", "zoner"]). The select screen shows up to three as chips under the roster. Known keys are translated (rushdown, grappler, zoner, balanced, aerial, trapper, counter, power); any other key is shown uppercased (storm-caller becomes STORM CALLER). The list lives in src/profile_tags.rs.
  • The select screen shows the nationality and the biography of the highlighted fighter under the roster (thugs and the boss appear with the Bosses filter). The Story mode stage card shows the profile of the stage boss.
  • Fighters without a profile (M.U.G.E.N content) keep showing description.
  • cargo test --release -p ultimate-mugen profile checks that every fighter file of assets/chars has a complete profile in the three languages.

Each animation is a list of frames:

  { "pose": "jab0", "ticks": 3 },

How an attack frame becomes a hit box

Frames drawn from pixel sprites take their strike box from the explicit box when given, otherwise from a standard box seeded by the hit part (low for feet and knees, high for the head, middle otherwise) and radius, trimmed to the sprite silhouette. The compiler then reshapes it to the proportions measured on 605 M.U.G.E.N characters (native/pixel_hit.rs, H = standing height, 96 units for height 100):

  • like a M.U.G.E.N Clsn1, the box spans from the body to the tip: it starts at most 0.10 H in front of the origin and reaches at least 0.60 H (the M.U.G.E.N median for punches is 0.72 H, kicks 0.80 H);
  • at least 0.36 H tall and never above 0.95 H or below the floor (M.U.G.E.N punches sit between -0.75 H and -0.33 H, kicks down to -0.05 H);
  • the standing hurtbox is 0.46 H wide (M.U.G.E.N median 0.46 H) and the crouching one 0.67 H tall (M.U.G.E.N median 0.67 H);
  • an explicit box is used as written, so keep it inside those proportions; the audit fails otherwise.

cargo test --release -p ume-engine --test it native_hitbox_audit:: checks every strike frame of the roster (height, reach, start, width, above the head, under the floor), and native_normal_reach prints and compares the reach and damage of the four stand normals of every fighter.

Built-in kits (extends). Fighters can inherit reusable capabilities with "extends": ["core", "ki_fighter", "clone_arts", "aerial_rush"] (crates/native/src/kits/): core provides universal launcher and escape_burst; ki_fighter provides abilities.fly, abilities.teleport, abilities.superSpeed, abilities.charge (customizable auraColor, shake, sound, explod) and a multi-hit ki_beam template (missTime, hitflag); clone_arts attaches autonomous shadow clones (helpers.clones); aerial_rush adds flight, super speed and double air-jump.

Finisher. A move with "kind": "finisher" (use throw or hits for the effect) is only available after a KO (RoundState = 3 and WinKO). When the final round ends by KO and the winner has a finisher, the round waits up to 6 seconds on "FINISH HIM" for the winner to perform it; performing it (or the timeout) ends the wait. Rosters with no finisher are unaffected.

Ultimate. A move whose id starts with ult_ is the fighter's ultimate, and every native fighter declares one (the command is ~D, DF, F, D, DF, F, x+y). The compiler spends the whole meter on it: cost defaults to 3000 (the three bars drawn by the HUD), the move gets a 70 % damage bonus where a normal super gets 30 %, and its super freeze lasts 75 ticks instead of 55. cargo test --release -p ume-engine --test it native_ultimates:: fails when a fighter has no ultimate, when the cost is not three bars, when the ultimate does not start from its command or drains the meter, or when the measured damage is below 380 or not above every one of the fighter's supers.

Combat traits

  • Automatic gatling. A move without cancels follows the genre rules: a normal cancels into any stronger normal (light < medium < heavy by the strongest hit level, ties by declaration order, so strings can never loop), ground normals link into crouching ones, air normals chain with air normals, and every normal cancels into every special and super on contact. Specials cancel into other specials only through explicit cancels; supers cancel out of any move.
  • Explicit routes. "cancels": ["strong", "rush"] on jab makes strong and rush accept jab on contact. A projectile special can be cancelled once its projectile touches the opponent. An air special may start from a ground launcher that lists it (uppercut, then dive).
  • throw (damage, bind [x, y] in front of the thrower, launch [vx, vy], at = grab frame, default 1). The grab HitDef fires on animation element at (give that frame a hit box), the victim is held on at + 1, takes the damage on at + 2 and is launched, so the animation needs at least at + 2 frames. Throws ignore guarding and whiff when the target is out of reach.
  • armor (hits absorbed, optional threshold = damage above which the armor breaks). From move start until the last hit frame the move takes 35 % chip damage and is not interrupted; once hits are spent the next hit staggers normally.
  • Multi-hit glue. Moves with three or more hits push the target away only a little on every hit except the last (so the whole string connects) and piercing projectiles (4+ hits) do not shove the target out of the beam. Set knockback explicitly to opt out.

Validate with cargo test --release --test it native_roster_lab:: -- --nocapture (every attack state must connect; prints damage and reach per move), --test it native_combo_routes:: (every declared cancel chains end to end) and python scripts/audit_native_moves.py.

Elements and stun

hits[] and projectile accept element (fire, ice, lightning, earth, wind, water) and stun (extra hit-stun ticks). The compiler adds the element's hit-stun and shake and tints the victim for a moment (PalFX): ice freezes longest (+16), lightning shocks (+22 and a 8-tick shake), fire burns red, earth shakes the screen, wind and water add a short tint. stun stacks on top and adds a 5-tick shake when none is set. Unknown elements are ignored.

hits[] and projectile also accept ownSound: true: hitSound then plays from the fighter's own sound bank (S prefix in M.U.G.E.N) instead of the common fight bank.

Power normals (Punch 3 and Kick 3)

Every native fighter that does not declare a move bound to z or c gets four extra normals at compile time (native/power_normals.rs): power_punch and crouch_power_punch on z (default key E, shown as Punch 3), power_kick and crouch_power_kick on c (default key D, shown as Kick 3). Each one reuses the animation, timing, guard height and cancels of the fighter's heaviest ground normal of that family (y then x for punches, b then a for kicks, crouching variants take the crouching normal), named <base name> Max. Hits deal 130 % damage, are promoted to heavy, gain 4 hit-stun and 2 hit-stop ticks when those are set, and push 25 % harder. Moves that cancel into the base normal also cancel into its power version, and the new moves appear in the pause move list. Declare your own z or c move to opt out. Air versions are not generated here.

All native fighters also receive two down-light-kick normals at compile time (native/low_normals.rs): lowkick on D+a while crouching and airlowkick on D+a in the air. They use the character's existing crouch-light-kick and air-kick animations, respectively, keep their pixel-art frames, and use low guard. The aerial version moves forward and downward to close short gaps. A fighter that already declares a move with the same id or D+a state/input keeps its authored move.

Energy charge (every fighter)

Every native fighter can charge its meter: hold R (the s / Start input; the pause key in a fight is Esc or P). The fighter enters state 3920, plays its powerUp animation on a loop with a blue glow and gains 9 to 48 power per tick (native/charge_ramp.rs, filling a 1000-power super in about one second) until the button is released (after at least 6 ticks) or the meter is full. The state is movetype = I, so a hit interrupts it, and a form-capable fighter still transforms with T once the meter reaches the form cost. The command is charge_cmd (/s) and shows as Charge Energy in the move list. The built-in AI charges only at level 3 or above, with less than 700 power, when the rival is more than 190 units away and is not attacking.

taunt, powerUp and defeat* have default versions if you do not define them. Other names get free numbers in file order. Add "id": 8801 to any animation entry to pin a fixed action number for custom scripts or p2Anim.

In-game and CLI Debug Tool

  • In-game (F2): renders translucent-filled Clsn1/Clsn2 boxes, amber pushbox, pivot crosshairs, velocity vectors, helper/target link tethers, stage bounds, top toolbar, and a 4-tab inspector (F4: Overview / Vars & Maps / Clipboard & HitDef / Console & Engine); F5 freezes simulation; F6 or . advances +1 frame; F7 cycles speed (1x/0.5x/0.25x/0.1x); F8 cycles box layers.
  • CLI: cargo run --release -p ume-devtools --bin ume-tools -- debug-fight <char1> [char2] [--frames N] [--only-moves] [--json] prints per-move frame data (startup, active, recovery, reach), clipboard, console, warnings, and cinematic events.

Air abilities (every special and super)

Every special and super with when unset or "stand" also gets an air version (state 20000 + ground state, label State -1, air <name>), entered with the same command while the fighter is airborne. The fighter hovers at the start of the move (drift kept at 40 %), gravity returns at 45 % after 12 ticks, the move ends into the jump fall state (50) with control, and touching the ground interrupts it with the landing state (52). Air versions deal 70 % of the ground damage, projectiles leave angled down (slope 0.85) so they reach a grounded rival, and each jump allows one air special (var(57), cleared on landing). Throws, flight moves and moves that declare when: "crouch" or "air" keep their own rules.

Pixel-art sprites (optional)

If assets/chars/sprites/<id>/ exists, the fighter is drawn from PNG files, the same way M.U.G.E.N fighters are drawn from sprites. Use transparent PNGs facing right, with the feet on the bottom edge and the same canvas size (400×400 RGBA) for every file of one fighter. Generate missing combat PNGs using generate_image with a validated canonical pixel-art anchor of that fighter (procedural or code-generated fighter art is forbidden).

meta.json holds {"refHeight": N}: the height in pixels of the standing body in 01_idle.png. Every pose of the fighter is scaled so that body is 100 units tall, so a lying or crouching sprite keeps the same pixel size. Without it each PNG is scaled to 100 units by its own height.

When awakeningPalette overrides hair, each sprite's frames.<stem>.awakeningHair supplies [left, top, right, bottom] in source pixels. Hair recoloring is confined to that rectangle; sprites without one retain their original hair. Web packing rescales these coordinates with the sprite.

Palette entries also apply to these PNGs: each pixel is matched to the shading line of a colour declared in art.style.colors, and the matching palette colour replaces it at the same shade. A palette key with no matching art.style.colors entry, or a colour nothing in the art resembles, is left untouched.

The web build does not read this folder from disk. scripts/build-web.sh runs ume-tools pack-sprites (crates/devtools), which writes one assets/chars/sprites/<id>.pack per fighter (images capped at 768 px, 256 colours stored as LZ4 sprites, see Sprite Container, meta.json anchors rescaled) into web/dist; the browser fetches a pack when the fighter is focused on the select screen or loaded for the fight, and the engine reads it through the same virtual folder. A failed download leaves the fighter without art, so the match waits for the pack and reports the failure.

Validate

cargo test --workspace --release

Review fighter art with ume-tools audit-sprites, which lists missing and reused poses, or in the game itself.

Browser sprite packs load asynchronously. A newly downloaded or replaced pack invalidates the affected native fighter’s cached previews and all palettes; other fighters keep their caches. Match loading waits for the chosen built-in fighters’ packs and reports download failures rather than starting with a cached procedural fallback. Imported native definitions without a bundled pack remain supported.

Share a fighter as a pack

A zip (or a mugen/ folder) that holds one UMF .json next to a sprites/ folder with 01_idle.png, the pose PNGs and an optional meta.json (axisX, axisY, refHeight per pose) is imported as a native fighter, with no .def. The marketplace installs it like any other pack. Goku SSJ4 UMF is the reference example.

M.U.G.E.N parity (exact migration)

tools/mugen2umf convert turns a M.U.G.E.N folder or zip into such a pack with identical behavior. The json carries a mugen block and art.type: "mugen":

  • mugen.cns, mugen.st, mugen.stcommon, mugen.cmd: the original state and command files, verbatim.
  • mugen.anims: every AIR action by number, with sprite, offset, ticks, flip, blend and alpha, scale, angle and every Clsn1/Clsn2 box.
  • mugen.info, mugen.mugenVersion, mugen.localcoord: the original .def [Info].
  • mugen.names: optional move names for the move list, keyed by command name.
  • sprites/: one indexed PNG per SFF sprite (exact indices and palette), sffpal_<k>.png for the SFF palettes, pal1.act..pal12.act, every sound as snd_g_i.wav, and meta.json (axes, sizes and palette of each sprite in SFF order).

The engine builds the fighter from these with the same code as a M.U.G.E.N character (ume_engine::loader::assemble_mugen_char), so states, commands, constants, animations, palettes and sounds are the same. UMF fields (profile, series, quotes, rivals, scripts) are layered on top. mugen2umf parity proves it move by move.

Native moves work on top of an exact fighter: each anim (and projectile anim) names a M.U.G.E.N action number ("anim": "3000"), and the moves compile like those of a native fighter, with commands m_<id>, chains, throws, projectiles and air variants. Their states live in a block of 100000 numbers above the highest original state, and their Statedef -1 routes run before the original ones, so original states are never replaced. parity compares the exact part without them and lists them under "Added by UMF", played from their real input.

SFF v1 palettes follow M.U.G.E.N: in a shared-palette SFF (header palette type 1), a sprite flagged "same palette" uses the character palette (the selected .act), never the private palette of the sprite before it (usually the 9000 portrait). Individual-palette SFFs still inherit from the previous sprite.

Fighter element

The optional top-level element field accepts fire, ice, lightning, water, earth, wind or neutral. The fight HUD shows the assigned element beside the fighter portrait, with a localized text fallback. This metadata has no effect on damage or match rules.
